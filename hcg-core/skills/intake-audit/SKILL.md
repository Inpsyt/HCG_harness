# Intake Audit — 프로토타입 인수 진단 (HCG 표준 · read-only)

UX파트가 바이브코딩으로 제작한 프로토타입을 프로덕트파트가 인수할 때, **무엇을 살리고 무엇을
다시 만드는지**를 판정하는 진단 규약. 프로토타입은 완성 코드가 아니라 **실행되는 기획서**다 —
인수 대상은 의도(화면 흐름·데이터 형태·기대 동작)이며, 코드는 그 참고자료다. 따라서 재제작
판정은 실패가 아니라 예정된 공정이고, 이 진단의 산출물은 비난이 아니라 **작업 계획의 근거**다.

## 두 가지 절대 규율

1. **코드 수정 금지.** 진단 중 발견한 문제를 고치지 않는다 — 전체가 "Noticed, not changed"다
   (CLAUDE-core §3). 진단과 수정이 섞이면 리포트의 객관성이 무너진다. 수정은 진단 리포트가
   확정된 뒤 별도 Task로 수행한다.
2. **근거 인용 없는 판정 금지.** 모든 판정에는 근거 출처를 단다 — 컨벤션 스킬의 조항,
   0차 자동검사의 실측 결과, `project.md` 「운영 규모」 대비 실측치 중 하나. "코드 품질이
   낮다" 류의 무근거 판정은 쓰지 않는다.

## 등급 정의

| 등급 | 의미 | 판정 조건 |
|---|---|---|
| **살림** | 그대로 재사용 | HCG 컨벤션 준수 + 0차 통과 + 해당 시 규모 실측 통과 |
| **수리** | 구조는 유지, 위반부만 교체 | 설계 의도는 맞으나 조항 위반(금지 라이브러리·직접 생성 등)이 국소적 |
| **재제작** | 프로덕트파트가 새로 구현 | 항상-재제작 영역 / 구조적 위반 / 규모 실측 불합격 / 0차 불통과 |

경계 판단 기준: **교체 범위가 파일 단위로 격리되면 수리, 여러 feature에 얽혀 있으면 재제작.**

## 입력 전제

- 프로토타입 저장소 (전체 read 권한)
- `.claude/project.md` 「운영 규모」 — 3차 실측의 기준값. **없으면 진단을 중단하지 말고**
  0~2차까지 수행한 뒤, 리포트에 "운영 규모 미확정 — 성능·규모 판정 보류, 전략파트 확인 필요"
  로 명시한다(질문으로 끝내지 않기 — verification-ladder 보고 규율 4).

## 사전 판별 — 하네스 부재·이종 스택 (0차보다 먼저)

이 스킬은 **진단 세션(프로덕트파트) 쪽 플러그인**으로 동작한다 — 프로토타입 저장소에 하네스가
설치되어 있을 필요가 없다. 다만 진단 시작 전에 `package.json`·설정 파일로 스택을 판별해
모드를 정한다:

| 판별 결과 | 모드 |
|---|---|
| HCG 계열 (Next.js + Prisma 등, 하네스 유무 무관) | **통상 진단** — 0~3차 전부. npm 스크립트가 없으면 폴백 명령(`npx tsc --noEmit`, `npx next build` 등)으로 0차를 수행하고, 없는 스크립트는 "없음"으로 기록 |
| 이종 스택 (Vite SPA · Supabase/Firebase 등 BaaS · 타 프레임워크) | **의도 추출 모드** ↓ |

**의도 추출 모드** — 조항 대조(2차)는 전 항목 위반이 자명하므로 항목별 판정을 생략하고
"스택 갭: <프로토 스택> → <HCG 표준>, 코드 이식 불가"를 **한 줄로만** 기록한다. 코드 살림
0%가 실패가 아니라 이 모드의 정상값이다 — **살리는 것은 코드가 아니라 스펙이다.** 산출물:

1. **계약 초안 역추출** (핵심 산출물) — 화면 목록·흐름, 데이터 모델(BaaS 스키마 → db-schema
   초안), 동작 명세(API 의도 → api-spec 초안). 확정은 세션+사용자 합의(contract-authoring).
2. **1차 항상-재제작 영역 위치** — 동일하게 수행 (auth·개인정보·결제가 BaaS에 위임되어
   있으면 그 사실 자체를 기록: 공통 인프라로의 교체 범위 산정 근거)
3. **외부 서비스 의존 목록** — BaaS·서드파티 API의 키·요금제(무료 티어 여부)·데이터 위치.
   실서비스 전환 시 요금·데이터 이전 리스크 판단 근거
4. **3차 실측 대신 로직 패턴 검사만** — 이식할 코드가 없으므로 실측은 생략하되, 프로토가
   증명한 동작 규모(전량 로드 UI 등 재설계 필요 지점)를 스펙에 주석으로 남긴다

> 의도 추출 모드가 반복되면 그것은 프로토타입 레인(스타터 킷) 부재의 신호다 — 진단으로
> 흡수하지 말고 UX파트 제작 환경을 HCG 계열로 옮기는 개선을 세션이 제안한다.

## 진단 절차 (4단계 · 순서 고정)

### 0차 — 자동검사 (기계 판정 · 반박 불가 영역)

표준 환경(npm)에서 실행하고 결과를 그대로 기록한다:

```bash
npm ci                      # 의존성 설치 재현 가능 여부
npx tsc --noEmit            # 타입 clean
npm run lint                # lint clean
npm run build               # 빌드 통과
npm test                    # 테스트 존재·통과 여부 (없으면 "없음"으로 기록)
```

추가 스캔 (grep/스크립트):

- **시크릿 하드코딩**: API 키·비밀번호·접속 URL 실값이 코드에 있는가 (`.env.example` 분리 여부 포함)
- **금지 의존성**: `package.json` 에서 TypeORM·SWR·Axios/ky·Redux/Jotai·Formik/Yup·Jest/Cypress/Mocha
  검출 (각 `*-conventions` 금지 목록)
- **라이선스**: 상용 서비스에 부적합한 라이선스의 패키지 유무
- **마이그레이션 파일**: `prisma/migrations/` 존재 여부 — 없으면 DB 구조가 서버에서 재현 불가

빌드·타입 불통과는 그 자체로 판정 근거가 되며, 해당 영역을 재제작 후보로 올린다.

### 1차 — 항상-재제작 영역 식별 (검사 생략 · 위치만 기록)

아래 영역은 **품질과 무관하게 재제작이 기본값**이다. 코드를 평가하지 말고 **어디에 있는지만**
식별해 기록한다 — UX파트도 이 영역은 흉내만 내면 된다는 것이 사전 합의의 전제다.

> 이 목록은 `codex-review` 트리거 ①~⑤와 동형이다(하네스가 이미 고위험으로 지정한 비가역 축).
> **항목 추가·완화 금지** — 개정하려면 하네스 레포 `CHANGELOG.md` 에 근거를 남긴다.

1. 스키마 마이그레이션 · 데이터 이관 경로 (`promoting-db-to-prod` 절차로 별도 수행)
2. auth · 권한 · 세션 경계 (공통 인프라로 교체)
3. 결제 · 외부 부작용 (메일 · 웹훅 · 서드파티 쓰기)
4. 동시성 · 트랜잭션 · 정산 invariant
5. 보안 표면 — 입력 검증 · 파일 업로드 · 인젝션 가능 지점
   - **개인정보(심리검사 결과 등 민감 데이터)의 저장·전송 방식 포함** — 평문 저장·마스킹 부재는
     검토 없이 재제작

### 2차 — 컨벤션 조항 대조 (판정 기준표)

| 검사 항목 | 근거 조항 | 등급 규칙 |
|---|---|---|
| ORM | `db-conventions` 「대체 ORM 도입 금지」 | Prisma 외 사용 → **재제작**(DB 접근 계층) |
| Prisma 클라이언트 | `db/backend-conventions` 「lib/db.ts 싱글턴 · 직접 생성 금지」 | `new PrismaClient()` 산재 → **수리** |
| raw SQL | `db-conventions` 「$queryRaw 파라미터 바인딩 · 문자열 보간 금지」 | 보간 검출 → **재제작**(해당 경로) |
| 입력 검증 | `backend-conventions` 「경계에서 Zod 검증」 | 서버 검증 부재 → **재제작**(해당 API) |
| API 구조 | `backend-conventions` 「route.ts 얇게 · 로직은 features/*/actions.ts」 | route에 로직 뭉침 → **수리**, 계층 자체가 없으면 **재제작** |
| feature 격리 | `backend/frontend-conventions` 「기능 중심 구조 · 영향 격리」 | 격리 없음(전역 뒤엉킴) → **재제작**(구조) |
| 서버 상태 | `frontend-conventions` 「TanStack Query · SWR/Axios 금지」 | 금지 라이브러리 → **수리** |
| 전역 상태 / 폼 | `frontend-conventions` 「Zustand / RHF+Zod · Redux/Formik 금지」 | 금지 라이브러리 → **수리** |
| 스타일 | `frontend-conventions` 「Tailwind · CSS Modules/styled-components 금지」 | 위반 → **수리** |
| UI 표준 | `frontend-conventions` 「HCG AX 표준(ax-wireframe)」 | 미적용 → **수리**(디자인 토큰 교체) |
| 접근성 | `frontend-conventions` 「a11y 준수」 | 시맨틱·키보드 부재 → **수리** |
| 에러 처리 | `frontend-conventions` 「TanStack Query 로딩/에러 처리」 | 실패 시 빈 화면/무반응 → **수리** |
| 런타임 자산 | `backend-conventions` 「node_modules 런타임 읽기 금지 · 비압축 자산」 | 위반 → **수리** |
| 환경 분리 | `templates/.env.example` 규약 | 개발/운영 설정 미분리 → **수리** |
| 파일 업로드 저장 | 1차 ⑤ + `backend-conventions` | 로컬 경로 직저장·용량 제한 부재 → **재제작** |
| 예약/배치 작업 | `backend-conventions` 「복잡 로직 services/ 분리」 | 개인 PC 상주 전제 방식 → **재제작** |
| 배포 호환 | 사내 배포 표준 (인스턴스 슬롯: `project.md` 배포 항목) | 표준 Docker/빌더 구성에 담기면 **수리**, 임의 구성 → **재제작** |
| contracts | `contract-authoring` | 부재가 정상(프로토엔 없음) — 진단이 코드에서 **계약 초안을 역추출해 제안**한다(작성 확정은 세션+사용자 합의, contracts 직접 생성 금지) |

### 3차 — 운영 규모 실측 (verification-ladder rung-3)

목록 · 검색 · 집계 · 리포트 · 문서 생성 경로를 `project.md` 「운영 규모」로 시드해 실측한다.
개발 시드(수십 건)에서는 인덱스 유무·N+1·풀스캔의 **신호 자체가 없다** — 실측 없는 성능 판정 금지.

- 판정 기준은 verification-ladder 체감 기준표를 그대로 인용한다:
  **~1초 쾌적 ✅ · 1~3초 괜찮음 ✅ · 3~10초 답답 ⚠️ · 10초~ 고장난 줄 안다 ⚠️**
- 코드 패턴 검사(실측 보완): 반복문 내 개별 쿼리(N+1) · 전량 로드 후 화면 절단 · 대용량
  원본 무가공 응답 · 요청마다 압축 해제되는 자산 → 검출 시 규모 가정과 대조해 등급 판정
- ⚠ 판정 경로는 **수리**(쿼리·인덱스 교정으로 해결) 또는 **재제작**(설계 자체가 규모 비대응)
  으로 분류하고, 원인을 사람 말로 기록한다

## 리포트 형식 (필수)

verification-ladder 보고 규율 4개를 따른다 — 판정을 숫자보다 먼저 · 사람이 판단할 수 있게 ·
근거 없는 추정 금지 · 질문으로 끝내지 않기.

```
# 인수 진단 — <프로토타입명> (YYYY-MM-DD)

## 결론 먼저
재제작 35% · 수리 25% · 살림 40% (파일 수 기준)
가장 큰 재제작 사유: <한 줄, 사람 말>

## 판정표
| 영역 | 등급 | 근거 (조항/실측) | 작업량 |
|---|---|---|---|
| 회원 화면 | 살림 | frontend-conventions 준수 · 빌드 clean | — |
| 검사결과 API | 재제작 | Zod 검증 부재(backend-conventions) + 1차 ⑤ | 대 |
| 결과 목록 | 수리 | 실측 8.2초 @10만건 — 반복문 내 쿼리 | 중 |

## 실측 (3차)
⚠️ 속도 — 결과 목록이 8.2초 걸립니다 (운영 규모 10만 건 기준)
   원인: 한 건씩 데이터베이스를 따로 불러서, 건수만큼 왕복합니다. …(사람 말)

## 항상-재제작 영역 위치 (1차)
- auth: app/api/login/* — 공통 인프라로 교체
- 개인정보: 검사결과 평문 저장 (features/result/actions.ts)

## 제안 계약 초안 (역추출 — 확정은 세션+사용자 합의)
- db-schema 초안: … / api-spec 초안: …

## Noticed, not graded
기준표 밖 관찰 사항 — 판정에 미반영. <취향·개선 아이디어는 여기로 격리>

## UX파트 공유용 요약 (한 문단 · 개발 용어 금지)
```

- **작업량은 대/중/소만** — 시간 단위 공수 추정("반나절이면 됩니다")은 금지.
- 재제작 판정에 비난 서술 금지 — 프로토타입에서 그 영역은 원래 흉내가 정상이다(1차 전제).

## 진단 이후

- 리포트 확정 → 재제작·수리 항목을 Task로 변환해 통상 경로(세션 직접 / `parallel-tasks`)로 수행.
- 진단에서 반복 검출되는 위반은 **UX파트 스타터 킷의 규칙 결함**이다 — 판정으로 끝내지 말고
  init 템플릿/CLAUDE.md 가드레일 개정을 세션이 제안한다(살아있는 문서 규율).
