이 파일은 `CLAUDE.md` 에서 `@import` 된다. 버전 관리되는 **살아있는 문서**다 — 모델 세대·플랫폼
변화로 규칙의 전제가 깨지면 개정하고, 근거를 README 변경 이력에 남긴다.

## 작업 라우팅

| 작업 형태 | 경로 |
|---|---|
| 기본 (결합된 기능·수정·버그) | 이 세션이 직접 수행 + §4 검증 |
| 독립 Task 여러 개 | `parallel-tasks` 스킬 |
| 대량 동질 작업 (코드모드·테스트 백필) | `migrate` · `test-gen` 워크플로 |
| contracts ↔ 코드 드리프트 점검 | `converge` 워크플로 |
| 코드 리뷰 | `/code-review` (ultra) — 내장 |
| 외부 교차모델 리뷰 (비가역·고위험 변경·릴리스 전) | `codex-review` 스킬 — 온디맨드·백그라운드, 게이트 아님 |

## Operating Rules §0~§5 (요약 — §4 의 상세 확장은 verification-ladder 스킬)

**§0 우선순위** — 규칙 충돌 시: ① 사용자 의도·결과 정확성 ② 가역성/안전(되돌리기 쉬운 쪽 선호)
③ 단순성 ④ 기존 코드베이스와의 일관성. **사용자의 명시 지시는 항상 이 문서 전체를 오버라이드한다.**
충돌은 소리 내어 명명하고 상위 규칙을 따른다.

**§1 진행 vs 질문** — 되돌리기 쉽고 틀려도 싸면 **가정을 명시하고 진행**한다. 되돌리기 어렵거나
비싸면(스키마·계약·auth·데이터 삭제/이관·결제·외부 부작용) **질문**한다. 모든 모호성마다 묻는 것
자체가 실패 모드다.

**§2 단순성** — 문제를 정확히 푸는 최소 코드. 추측성 기능·요청 없는 설정성·불가능한 상태의 에러
처리 금지. 단, 문제의 실제 복잡도에는 맞춘다 — 호출처 2+ 전 추상화 금지, 주변 코드의 추상화
수준을 유지한다.

**§3 수술적 변경** — Task 가 요구하는 것만 손댄다. 인접 코드 리포맷·리네임·리팩터 금지. 무관한
문제를 발견하면 조용히 고치지 말고 **"Noticed, not changed"** 로 끝에 보고한다.

**§4 검증** — 작업을 검증 가능한 목표로 바꾸고, 허용되는 **가장 강한 rung** 으로 검증한다:
① 자동화 테스트(변경 전 실패→후 통과) ② 타입/lint/빌드 clean ③ 실행 스모크 ④ 명시 수용기준+사람.
가드 2개 — anti-overfit("코드가 틀려도 이 체크가 통과할 수 있나?") · weak-criteria(성공이 미정의면
기준 2~3개를 제안하고 명시한 기본값으로 진행). 검증을 통과한 작업 단위는 **커밋**한다 — git 이
세션 간 핸드오프·재개의 원장이며, 커밋 메시지에 검증 결과를 한 줄 요약한다.

**§5 재앵커링** — 크거나 비가역적인 행동 전, **목표/제약/검증 방법**을 한 줄로 재진술한다.
