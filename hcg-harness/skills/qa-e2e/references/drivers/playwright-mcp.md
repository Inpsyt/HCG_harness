# Driver — Playwright MCP

MCP 서버가 별도 브라우저를 띄우고 도구 호출로 조작한다.

**강점**: 접근성 트리 스냅샷·네트워크 로그·콘솔 로그가 구조화돼 나와 판정이 정확하다. 사람 없이
반복 실행된다. 시크릿/격리 컨텍스트가 기본이라 세션 오염이 없다.

**약점**: 사용자의 기존 로그인 세션을 못 쓴다. OTP·SSO·결제는 사람 개입이 필요하고, 그 순간
"사람이 이 브라우저를 볼 수 있는가"가 문제가 된다. MCP 서버 설치가 전제다.

---

## 도구 확인

세션에 `mcp__playwright__*` 도구가 없으면 `ToolSearch` 로 조회한다:

```
ToolSearch: "select:mcp__playwright__browser_navigate,mcp__playwright__browser_snapshot"
또는 키워드: "playwright browser navigate click snapshot"
```

없으면 MCP 서버가 안 붙은 것이다. **이 세션에서 설치·인증을 대신 할 수 없으므로**
`playwright-local.md` 로 폴백하거나 사용자에게 연결을 요청한다.

`mcp__chrome-devtools__*` 계열이 있으면 그것도 같은 방식으로 쓴다 — 네트워크·성능 추적이 더 강하다.

## 기본 루프

```
navigate → snapshot → (스냅샷에서 대상 ref 확인) → click/type → snapshot → 검증
```

- **스냅샷이 셀렉터다.** 접근성 트리에서 요소의 ref 를 얻어 조작한다. CSS 셀렉터를 지어내지 않는다
- 스냅샷은 사람이 보는 것과 동등한 정보다. 여기 없는 텍스트는 화면에 없는 것이다
- 액션 후 반드시 새 스냅샷으로 결과를 확인한다. "클릭했으니 됐겠지"는 검증이 아니다

## 인증 처리

세션이 비어 있으므로 매번 로그인해야 한다. 순서대로 시도한다:

1. **dev 우회** — 빠른 로그인 버튼, 고정 OTP(dev 는 아무 6자리 통과 등), 인증 스킵 플래그.
   `_detect.md` §5 에서 확인한 것
2. **테스트 계정 + 사용자가 알려준 비밀번호** — 사용자가 **자발적으로 제공한** 테스트 계정 자격증명은
   입력해도 된다. 사용자의 개인 계정 비밀번호를 요구하지는 않는다
3. **OTP·SSO·결제** — 사람이 화면을 봐야 한다. Playwright MCP 브라우저가 사용자에게 보이지 않으면
   이 시나리오는 `blocked` 다. Claude for Chrome 으로 전환하는 게 정답

**로그인 상태 재사용**: 한 번 로그인한 컨텍스트를 유지해 여러 시나리오를 이어서 돈다. 매 케이스마다
새로 로그인하면 rate limit·계정 잠금에 걸린다.

**영역별 격리**: 관리자/사용자처럼 세션 저장소가 다른 영역은 **별도 컨텍스트**로 분리한다.

## 증거 수집

| 무엇 | 도구 |
|---|---|
| 네트워크 요청 | `browser_network_requests` — 메서드·URL·상태코드가 그대로 나온다 |
| 콘솔 | `browser_console_messages` — 에러/경고 |
| 화면 | `browser_snapshot`(구조) · `browser_take_screenshot`(이미지) |
| 서버 되읽기 | `browser_navigate` 로 GET API 를 열거나, 별도로 `curl` |

**네트워크 로그가 이 드라이버의 최대 강점이다.** `results.json` 의 `evidence` 에 요청 목록을
그대로 옮긴다 (`POST /api/x 200 ×26`).

**스크린샷은 필요할 때만.** 스냅샷 텍스트가 대부분의 판정에 충분하고 훨씬 싸다.

## 조작 주의

- **속도.** 도구 호출은 사람보다 훨씬 빠르다. 앱이 이탈/부정행위/rate limit 을 감지하면 오탐이 난다.
  그런 앱에서는 액션 사이에 의도적으로 간격을 둔다
- **대기.** 고정 sleep 대신 요소 등장/네트워크 완료를 기다린다. Next.js dev 는 첫 진입이 느리다
- **탭 관리.** 새 탭이 열리는 플로우(외부 결제·새 창 가이드)는 탭 목록을 확인하고 대상 탭을 명시적으로 고른다
- **파일 업로드/다운로드**는 MCP 브라우저의 파일시스템 기준이다. 경로가 로컬과 다를 수 있다

## 이 드라이버에서 흔한 함정

- **빈 스냅샷** — 페이지가 아직 렌더 중이거나 인증 리다이렉트를 탄 것이다. URL 을 먼저 확인한다
- **"요소를 못 찾음"** — 앱 버그가 아니라 스냅샷 시점 문제인 경우가 대부분. 다시 스냅샷을 뜬다
- **iframe** — 결제창·에디터는 iframe 안이다. 프레임을 명시적으로 다뤄야 한다. CSP `frame-ancestors`
  로 막힌 페이지는 iframe 검증이 아예 불가하다 (`blocked`)
- **시크릿 컨텍스트 = 캐시 없음** — 첫 로드가 매번 느리다. 성능 이슈로 오인하지 않는다
- **브라우저가 사용자에게 안 보인다** — 사람 개입이 필요한 순간 막힌다. 그 시나리오는 시작 전에
  미리 식별해 두고 드라이버를 나눈다
